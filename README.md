# deslop-ko

한국어 웹을 위한 AI 슬롭 검사기. **한글 조판**과 **시각 슬롭**을 함께 본다.

기존 도구는 전부 영어 기준이라 한글 조판을 못 본다. 실측해보면 그렇다 —
kill-ai-slop과 impeccable을 한국어 랜딩에 돌려 나온 228건 중 한글 조판 지적은 **0건**이었다.
`word-break: keep-all` 이 없어 어절 한가운데서 줄이 끊겨도, 한글 폰트가 스택 맨 앞에 있어
영문·숫자까지 거칠게 그려져도, 어느 도구도 말해주지 않는다.

그렇다고 한글 조판만 봐서는 안 된다. 그건 이 저장소가 직접 겪은 실패다 —
처음에는 조판 규칙만 만들었고, 그 결과 그라디언트 텍스트와 글로우가 가득한 페이지에
"지적할 것이 없습니다"라고 답했다. 심지어 폰트 순서를 고치라는 우리 조언을 따르다
Inter를 넣어 새 슬롭을 하나 만들었고, 우리 스캐너는 그것도 보지 못했다.

**규칙 텍스트를 베끼지 않는 것과 같은 영역을 다루지 않는 것은 다른 얘기다.**
그래서 시각 축을 직접 썼다. 우선순위는 실측에서 정했다 — 두 기존 도구가 서로를 모르는 채로
**둘 다 잡은 것**은 취향이 아니라 합의이므로 그것부터 승계했다.

```bash
node scripts/scan.mjs ./my-site
```

의존성 없음. LLM도 API 키도 필요 없다. 그래서 CI에 붙고, 재현되고, 반박할 수 있다.
**아무것도 자동으로 고치지 않는다.** 보고만 하고 결정은 사람이 한다.

## 핵심 — CSS만 봐서는 판정할 수 없다

같은 사이트, 같은 속성, 정반대 판정이다.

| 선택자 | 값 | 실제 텍스트 | 판정 |
|---|---|---|---|
| `.hero__title` | `letter-spacing: -0.03em` | `AI를 배우는 가장 빠른 방법` | 정상 — 한글 굵은 고딕은 음수 자간이 정석 |
| `.hero__title--brand` | `letter-spacing: 0.02em` | `GPTERS` | 정상 — 라틴 대문자는 양수 자간이 정석 |

한쪽만 보고 규칙을 만들면 반드시 틀린다. deslop-ko는 **선택자를 HTML에 매칭해
그 스타일이 실제로 어떤 언어의 텍스트에 붙는지 확인한 뒤에** 판정한다.

BEM 수식자도 합쳐서 본다. `.title--wide` 에 자간만 있고 굵기는 `.title` 에 있어도,
같은 요소에 붙는 선언을 모아 "굵은 한글에 양수 자간"인지 판정한다.

## 규칙

### 1단계 · 한글 조판 (구현됨)

| ID | 무엇 | 왜 |
|---|---|---|
| `ko-word-break` | `word-break: keep-all` 부재 | 없으면 어절 한가운데서 줄이 끊긴다 — "가장 빠른 방 / 법" |
| `ko-font-order` | 한글 전용 폰트가 스택 맨 앞 | 영문·숫자까지 그 폰트의 라틴 글리프로 렌더된다 |
| `ko-line-height` | 한글 제목의 행간 1.25 미만 | 한글은 받침 때문에 시각적 높이가 커서 받침이 윗줄에 닿는다 |
| `ko-letter-spacing` | 한글 굵은 제목에 양수 자간 | 이미 꽉 찬 글자를 벌리면 낱글자가 흩어진다. 국내 관행은 -0.02em ~ -0.04em |
| `ko-split-word-break` | 글자 분해 애니메이션에 어절 래퍼가 없음 | 글자를 낱개 inline-block으로 쪼개면 `keep-all` 이 적용될 텍스트 노드가 사라진다 |

### 1단계 · 시각 슬롭 (구현됨)

이 축은 언어를 가리지 않는다. 한국어 페이지가 아니어도 성립한다.

| ID | 무엇 | 왜 |
|---|---|---|
| `gradient-text` | 글자를 그라디언트로 채움 | AI 페이지의 가장 흔한 표식. 대비를 예측할 수 없고 정보는 늘지 않는다 |
| `glow-shadow` | 그림자에 색을 넣음 | 실제 그림자는 빛을 가려 생기므로 색이 없다 |
| `oversized-shadow` | 번짐이 40px 이상 | 요소보다 큰 그림자는 물리적으로 성립하지 않는다 |
| `glassmorphism` | `backdrop-filter: blur` | 뒤에 오는 것에 따라 대비가 매번 달라져 가독성을 보장할 수 없다 |
| `default-font` | 본문 서체가 Inter·Arial·system | 아무도 고르지 않았을 때 나오는 서체. 면적이 가장 큰 결정을 안 한 셈이다 |
| `low-contrast` | WCAG AA 미달 | 취향이 아니라 측정값. 브랜드 색 위 흰 글씨에서 자주 나온다 |
| `borrowed-brand-color` | 국내 플랫폼 브랜드 색을 토큰으로 | #FEE500·#03C75A 등은 한국 사용자가 그 서비스로 인식한다 |

마지막 하나가 이 축의 한국 오리지널이다. "친근한 한국 서비스 느낌"을 시키면 나오는 결과다.

### 2단계 · 한국어 카피 (작업 중)

카피는 문체 프로파일(`VOICE.md`) 대비로 판정한다. "이건 나쁜 문장이다"가 아니라
**"이건 당신 문장이 아니다"**로. 보편 금지 목록은 한국어에서 오탐을 낸다.

## 설계 원칙

### 오탐은 정탐보다 비싸다

한 번이라도 정상 조판을 지적하면 사용자는 스캐너 전체를 안 믿는다.
그래서 모든 규칙은 **오탐 조건을 함께 문서화**하고, 테스트도 오탐 케이스를 더 많이 쓴다.

판정 근거가 없으면 판정하지 않는다. 선택자에 매칭되는 텍스트를 못 찾으면 넘어간다.

### 규칙은 근거로 만든다

"내 느낌에 이건 촌스럽다"로 규칙을 만들지 않는다.
사람이 쓴 실제 사이트와 AI가 생성한 카피를 나란히 놓고, **AI 쪽에만 반복되는 것**만 채택한다.

이 방법으로 "AI 시대"를 기각했다. 슬롭처럼 들리지만 스파르타클럽 헤드라인이
`AI 시대, 미래를 돌파하는 힘` 이다. 사람이 쓰는 표준 마케팅 관용구다.

### 리포트가 곧 교재

자동 수정이 없으니 사용자는 매 지적을 읽는다. 그게 유일하고 확실한 교육 접점이다.
지적 하나에 **왜 · 수정 · 주의** 세 줄이 반드시 붙는다.

## 사용법

```bash
node scripts/scan.mjs <경로>                  # 검사
node scripts/scan.mjs <경로> --json           # CI용
node scripts/scan.mjs <경로> --only=ko-word-break
node scripts/scan.mjs <경로> --skip=ko-line-height
node scripts/scan.mjs <경로> --include-archives   # 아카이브까지 포함
```

### 무엇을 검사하지 않는가

`steps/`, `v1/`, `bg-samples.html`, `making.html` 같은 **아카이브와 실험 파일은 기본 제외**다.
최종 산출물이 아니기 때문이다. 이게 없으면 리포트의 대부분이 노이즈가 된다.
실측에서 한 스캐너가 90건을 보고했는데 그중 78건(87%)이 실습 스냅샷이었다.

`*.md` 도 제외한다. 문서의 슬롭은 성격이 달라서 별도 스킬이 맡는다.

### 의도한 것이면 면제

사유를 반드시 적어야 한다.

```css
/* deslop-ko-ignore ko-letter-spacing: 워드마크라 의도적으로 벌린 자간 */
```
